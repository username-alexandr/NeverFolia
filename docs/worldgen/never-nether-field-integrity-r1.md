# NeverNether FIELD-R1: surface-fluid fix and read-only voxel audit

Status: **candidate**, not a server release or a completed field-world repair.
Baseline source: `81b855876dce4971ef77c4d51736650eff46f79e`.
Worldgen identifier stays `NN-DEV-1`; finalized core manifest revision is `NN-FIELD-R1`.

## Confirmed code path and narrowly scoped fix

The raw core builder's Basalt Deltas floor surface rule can replace a top
netherrack block with source lava (`level=0`) using a 3D noise threshold.
A floor-depth condition is not a proof that a shelf has a supporting block below,
a bounded basin, or retained walls. This is a plausible contributor to the
reported lava shelves, not a reproduction of the supplied screenshot locations.

The **finalized TEST1 core builder** now changes that single surface-rule result
to solid magma. It requires exactly one matching biome rule and one lava result;
an upstream contract change stops the build instead of silently applying a broad
replacement. The combined TEST1 importer uses this finalized core builder too.
The raw diagnostic core builder is intentionally unchanged.

This conservative patch removes an unvalidated fluid-placement path. It does
**not** implement elevated lava lakes, generate new lavafalls, disable all lava,
or claim every reported hanging-lava instance is fixed. Bounded lakes need their
own deterministic terrain validation and runtime tests.

Unchanged by this patch:

- Density functions, cave topology, biome selection and dimension bounds.
- Primary lava level `Y=32` and the default lava fluid.
- Vanilla spring features and fluid simulation.
- Generated body `Y=-128..383`; roof construction zone `Y=384..895`.
- Overworld/End code, source importer selection, and player-built areas.

The pack's content fingerprint changes. Never remove an existing world's guard
lock to force this candidate into an old world. Use an isolated, newly generated
test world with the matching NeverFolia runtime and the normal fingerprint guard.
No old chunks are edited or regenerated by these scripts.

## Read-only persisted-block audit

`scripts/audit-never-nether-field-integrity.py` reads exact selected **FULL**
chunks from a stopped-server copy of the actual Nether region directory. It
uses the existing NBT/paletted-state decoder and does not load or generate chunks
on a live server. No blocks, input region files or locks are written.

Example (chunk coordinates, not block coordinates):

```sh
python3 scripts/audit-never-nether-field-integrity.py \
  --region-dir /absolute/path/to/stopped-copy/nether/region \
  --chunk=-1,0 --chunk=0,0 \
  --min-y -128 --max-y 383 \
  --pocket-limit 64 \
  --output /absolute/path/outside-region/nether-integrity.json
```

Pass the actual directory rather than assuming a server's dimension layout.
Start with a small group of neighboring chunks around the observed issue. The
report records the inspected chunks and Y range; it is not a whole-world scan.

The report distinguishes:

For the current R14 profile the read-only body scan may cover `Y=-128..511`.
The protected bedrock roof at Y=512 and the empty technical padding Y=513..527
are verified separately by the R14 roof audit; they are not treated as cave
volume.

- Small six-connected air components fully surrounded by recognized natural
  rock within the inspected volume, with positions, sizes and bounding boxes.
  Enclosed components up to the configured limit are also bucketed as
  `1`, `2–4`, `5–16` and `17–64` blocks so single-voxel and tiny cavity
  regressions are visible separately from larger intentional cave pockets.
- Components touching missing chunks or the inspected Y boundary: coverage is
  **unknown**, not assumed solid or empty.
- Components intersecting saved structure start/piece bounding boxes from the
  selected chunks: reported separately, not treated as geological defects.
- Source and flowing lava; sources with air underneath are inspection candidates,
  **not automatically bugs**, because legitimate lavafalls can look like this.
- A stricter `hanging_source_lava_shelf_candidates` metric marks a source-lava
  block only when it has air below and at least two horizontal source-lava
  neighbours outside saved structure boxes. This is intended to surface the
  reported hanging horizontal lava shelves while leaving isolated lavafall/edge
  sources in a separate diagnostic count. It is still a heuristic, not an
  automatic proof of a generation defect.
- Non-air blocks in the roof zone: observations only, possibly player builds.

There is no blanket air-filling pass. Small enclosed caves can be intentional;
structure starts outside the selected chunks can also remain unknown. Findings
require inspecting their origin and the affected world. A spectator screenshot
alone does not establish the stored block states.

Missing/non-FULL chunks, malformed sections/containers, invalid packed data and
coordinate mismatches fail the command. A successful exit means the input was
read, **not** that its world generation is defect-free. A failed run does not
create a new report; an old report from an earlier invocation is not evidence
for the failed run. JSON output must be outside the audited region directory.

The approved baseline is the existing balanced placement document and JSON spec,
not a newly invented set of dungeons. The selected custom set remains 20:
Hearths (3), Dungeons and Taverns (12), Explorify (1), Structory Towers (3),
and the Repurposed Structures / Better Monuments Nether monument (1), plus the

- `Hearths v1.0.5.dp.zip`
- `Dungeons and Taverns v5.3.2.zip`

synthetic fixtures and must not be represented as a real 20-structure import.
The existing source-lock/license-safe import policy remains in force.

## Validation and remaining release gates

Run `python3 scripts/test-never-nether-field-integrity.py` for the regression
suite. It covers negative-coordinate chunk seams, incomplete coverage, protected
structure boxes, palette validation, source/flowing lava distinction, report
truncation, unchanged input bytes, and an end-to-end synthetic Anvil-file CLI run.
Pack tests prove that only the intended surface result changes in noise settings,
density/dimension resources remain identical, and two builds have identical
resource content. This is **not** a runtime chunk-order determinism test.

The dedicated CI workflow runs these tests, the existing spec/decoder/importer
self-tests, builds the finalized core, injects and verifies its fingerprint, and
publishes checksums with exact source SHA. It does not compile a server JAR.

Before calling this a field-ready server build, still require:

1. A compatible Java 25 / NeverFolia server build and successful registry startup.
2. Real newly generated Nether chunks, saved after normal stop, with affected
   positions and surrounding coverage inspected using this audit.
3. Runtime strict chunk-order determinism and fluid-tick observation.
4. Actual source-archive import, structure registry/placement/bounding-box tests,
   and the normal combined Overworld + Nether regression gates.
