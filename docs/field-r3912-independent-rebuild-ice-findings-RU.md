## Что ставить пользователю

Minecraft Java именно 26.2. Для модуля нужны Fabric Loader >=0.19.3 и Java >=25. Поместить JAR в mods используемого КЛИЕНТА, не сервера. Отдельный Fabric API не требуется. Удалить только старую копию того же модуля, если такая уже была установлена. Перезапустить игру.

Мод включает переводы. Swift Soar — «Стремительный полёт», Wither Coated — «Иссушающее покрытие». Служебные контроллеры фильтруются при составлении категорий зачарованных книг и поиска. Книги в существующем инвентаре не удаляются; реестр, эффекты, лут и экипировка не меняются.

Без Fabric доступен только ресурс-пак: внутренний ZIP поместить в resourcepacks и включить выше других переводов D&T. Он переименовывает Bug Enchant в «Служебное зачарование», но НЕ скрывает книги. Русский язык должен быть выбран в игре. При использовании мода отдельный ресурспак необязателен.

Графический клиент НЕ запускался, применение Mixin НЕ выполнялось. Проверка предиката на сервере и статическая проверка адресов не подменяют клиентский тест. Совместимость с другими модами, реальное отображение переводов и скрытие книг в GUI требуют ручной проверки. Получение книг в луте и работа боевых эффектов этим прогоном не проверялись.

## Что установлено по подводному льду

Прочитан фактический материализованный NeverOverworldFlood.java из закреплённого DEBUG R38: SHA-256 e9a68ef34c78988f1d584cbf14889f312872cc9f04b53aa9b44c744157d6bc27. Строки 533–603:

1. weatherSubmergedSurface рассматривает колонку только при WATER на Y=128.
2. При спуске он заменяет встреченный снег/обычный/плотный/синий лёд водой.
3. Первый неразрешённый твёрдый блок прекращает спуск. MAGMA_BLOCK не является разрешённой поверхностной накладкой или выветриваемым грунтом; следовательно, лёд под магмой этот путь не посещает.

Это конкретное ограничение алгоритма и правдоподобное объяснение части фрагментов под магмой. Оно ещё НЕ доказывает происхождение каждого фрагмента на скриншотах или тип всех тёмных кубов. Массовое удаление льда не выполнялось: назначение льда в постройках и нормальных биомных объектах необходимо сохранять.

Также проверены реальные источники BlueIceFeature.java (9d6e5635ca18677101f72e88711d8212eeb9840ddf0bcee9c0410c3f32532224) и IcebergFeature.java (bb9f52ee12da31b2f98e8010fa81c82daa1ba132985708f2d60a20ac79b27756). Синий лёд проверяет уровень моря WorldGenLevel; айсберг выбирает Y через ChunkGenerator.getSeaLevel. Фактическое численное значение этих вызовов в этом шаге не измерялось — расхождение уровней не объявлено доказанным.

Классы обнаружены по составу точного R39.9 JAR, а не по предполагаемым названиям: BlueIceFeature, IcebergFeature, SnowAndFreezeFeature. Для них сохранён javap -c -p и контрольные суммы. SnowAndFreezeFeature использует MOTION_BLOCKING и Biome.shouldFreeze. В диагностическом архиве нет каждого ванильного Java-исходника; отсутствующий исходник не подменён реконструкцией.

## Сохранённые неудачи

Предыдущие попытки данного workflow 36394592925 и 36394746725 завершились до пересборки клиента: инспектор ошибочно ожидал FreezeTopLayerFeature, которого нет под этим именем. Исправлен сам инспектор: фактические имена обнаруживаются из проверенного JAR. Эти попытки не засчитаны успешными, их сохранённые ошибки не удалены. В окончательном запуске все этапы завершились.

## Граница итерации

Изменён только новый диагностический workflow в отдельной ветке и добавлен этот отчёт; серверные классы и исходная реализация модуля из PR 24 не менялись. Слияний нет. Исполнение — GitHub Actions, не локальный контейнер чата. Независимая локальная проверка скачанных ZIP не выполнялась из-за ClientError среды.

Готовое клиентское дополнение можно вручную проверить без пересоздания мира и без замены R39.11. Основные оставшиеся серверные вопросы — подводный лёд, остаточные воздушные полости, полная работа мобов и ресурсные пробелы данжей — не объявлены закрытыми.
