# FIELD-R38: проверка кандидата в отдельном мире

Этот документ не означает, что исправление воды принято. Итог каждого прогона записан в `r38-live-qa.json`; отсутствие файла или `pass: false` не является успешной проверкой.

## Какой комплект проверяется

- Исходники согласованного кандидата: `c6e522c65e5ecd0852c27d724c652189464f51cc`.
- Исходная ветка до продолжения: `fix/neveroverworld-r23-cave-enchants`, `8b52c3f30df55452a06d4ceece2ad84add52ee61`.
- Изменения находятся в draft PR #12, в `wip/neveroverworld-r37-continuation`. Слияние в исходную ветку не выполняется автоматически.
- Сборка и живые проверки: GitHub Actions run `36308250793`.
- В комплект должны входить `server.jar`, `NeverOverworld.zip`, `NeverNether.zip`, `SOURCE-COMMIT.txt` и `SHA256SUMS.txt`. Нельзя брать JAR из одного прогона, а датапаки из другого.
- `build-input/BASELINE-NOT-R38-8b52c3f.jar` из прежнего локального архива — не этот кандидат.

## Что изменено в продолжении

Мигратор больше не передаёт исходный объект `ZipInfo` в `writestr`: изменение смещений записи ломало последующее контрольное чтение ZIP. Теперь используются копии метаданных, проверяются все выходные полезные данные и комментарий архива, а замена файла производится после закрытия читателей. При ошибке исходный архив остаётся на месте. Девять регрессионных тестов запускаются до сборки Java.

Старая проверка импорта требовала промежуточные команды `summon` + `ride`, хотя финальная миграция уже заменяла их на `neverfolia:dnt drowned_mount`. Валидатор теперь различает две точные формы и отражает тип контроллера в отчёте. Произвольные дополнительные команды не допускаются. Для отдельной строгой проверки конечного пакета предусмотрен флаг `--require-native-controller`.

## Порядок проверки, не затрагивающий рабочий мир

1. Скачать артефакт именно указанного прогона. Проверить `SOURCE-COMMIT.txt` и выполнить `sha256sum --check SHA256SUMS.txt` в распакованном каталоге. При отсутствии контрольных сумм или любого обязательного файла комплект не готов даже для этого сценария.
2. Использовать Java 25. Создать новый, ранее не существовавший тестовый каталог. Не распаковывать комплект в каталог рабочего сервера, не использовать его `world`, `plugins`, настройки или базу данных.
3. Поместить два датапака в `world/datapacks/` нового тестового каталога. Установить seed `-4651369264513492755` до первого создания мира.
4. Для первоначальной изолированной проверки использовать `server-ip=127.0.0.1`, отдельный порт и только необходимые тестовые компоненты. Не переносить из CI настройки `online-mode=false` на публичный сервер. Соглашение Minecraft EULA прочитать и принять самостоятельно до запуска.
5. Запустить `java -Xms1G -Xmx4G -jar server.jar --nogui`. Проверять ошибки загрузки датапаков до осмотра мира. Закончить через `stop`, а не принудительным завершением процесса.

Минимальные параметры нового `server.properties` для ручного осмотра:

```properties
level-name=world
level-seed=-4651369264513492755
initial-enabled-packs=vanilla,file/NeverOverworld.zip,file/NeverNether.zip
server-ip=127.0.0.1
server-port=25595
online-mode=true
view-distance=6
simulation-distance=6
spawn-protection=0
difficulty=normal
```

Не открывать тестовый порт наружу без отдельного решения. Для удалённой машины возможен SSH-туннель: локальный порт перенаправляется на её `127.0.0.1:25595`. Этот документ не изменяет сетевые настройки сервера.

## Места из отчёта об ошибках

| Что смотреть | Положение камеры / область из скриншотов |
|---|---|
| Прямоугольные стены и основания | примерно `63 159 2`, `43 159 52` |
| Пещерная вода | `14 52 11`, `8 52 14`, `-53 23 50` |
| Стык воды и рельефа | примерно `6 154 -1` |
| Основания под наземными данжами | примерно `193 163 73` |
| Подводный данж и спавнер | примерно `-3217 46 -3398`, `-3259 46 -3397` |

Это координаты наблюдения, а не доказательство, что именно в клетке камеры обязан находиться воздух. Из-за изменений генерации структура в новом мире может располагаться иначе. Изолированный CI ограничен 48 целевыми чанками возле первых участков; дальний подводный данж из скриншотов не следует считать автоматически проверенным тем же прогоном.

Для проверки активации trial spawner нужен обычный игрок в выживании. Режим наблюдателя подходит для осмотра стен, но не является проверкой обычного появления мобов. Учитывать состояние и перезарядку самого спавнера.

## Как читать результаты

- `r38-pack-upgrader-tests.json`: проверки мигратора ZIP, не игровой генерации.
- `r37-java-unit.json`: проверки фактических Java-методов с ограниченными тестовыми заменами; не полный сервер.
- `r37-import-qa.json`: сохранность закреплённых исходных NBT и конфигураций спавнеров.
- `r38-live-controller.json`: выполнение контроллеров на сервере в потоке региона, включая отмену появления и посадки на ездовую сущность.
- `r38-natural-trial.json`: два исходных варианта trial spawner с подключённым игроком в выживании; не все боссы и не все способности.
- `r38-water-provenance.json`: состояние воды до/после цепочки LIGHT; допустимые изменения сухих шахт указаны отдельно.
- `r38-live-qa.json`: живые фазы, сохранение, перезапуск, сравнение порядка генерации и итоговая приёмка.
- `r38-reachable-resources.json` отдельного диагностического прогона: ссылки на пулы и NBT, достижимые от естественных structure_set; это не проверка всей добычи, процессоров и сценариев.

## Что этот комплект не обещает

Старые квадратные основания и уже записанные ошибки воды не удаляются автоматически. Отключение добавляемых ядром островов не является разрешением удалять полы и фундамент из самих исходных шаблонов.

Пул `betterwitchhuts:mobs` содержит совместимые шаблоны ведьмы и кошки. Для отсутствующего в закреплённом источнике `pale_residence/decor_inside` в этой ветке пока используется явный необязательный пустой элемент; восстановление оригинального декора не заявляется.

Успешная компиляция, прохождение двух вариантов trial spawner или отсутствие нескольких сообщений в консоли не подтверждают исправность всех миров, данжей и боссов. Не применять кандидат к рабочему миру до разбора фактических результатов.
