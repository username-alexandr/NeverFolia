## Новая правка

Четыре публичных входа очистки получают ранний отказ для persisted status FULL:

1. Flood.reweatherSubmergedSurface;
2. FloodConnectivityR15.apply;
3. FloodConnectivityR15.reconcileSeams;
4. SubmergedRemnants.apply.

Основной Flood.apply и другие существующие методы уже защищены от FULL; их условия не снимаются. Обработка новых чанков до FULL сохраняется. Цель — исключить изменение уже готовых блоков при повторном вызове генерационных процедур, включая путь LIGHT. Сами световые данные эта правка не отменяет.

В репозитории находится точный hash-checked преобразователь `qa/field-r398/build_guarded.py`. Он создаёт Java-файлы из настоящих материализованных исходников, сохраняет diff и компилирует их против библиотек R38 на Java 25. Это реальное изменение генерируемых исходников, но **инкрементальная компиляция, не полный Gradle build**.

Сохранена уже проверенная политика R396 (`y >= floor` для удаления выбранного блока с контактом с водой). Экспериментальный AIR-only R395 присутствует в кандидате, но выключен без `-Dneverfolia.r395OceanClosure=true`. Датапаки R39.3 и NeverNether не меняются. Клиентский мод UI в этом кандидате не собирается и не устанавливается.

## Тесты и границы доказательства

`R398FullChunkQa` создаёт синтетический стенд только в новом CI-мире, на настоящем region-owned LevelChunk со статусом FULL. Для каждого из четырёх прямых вызовов сохраняются и сравниваются все 262144 состояния блоков чанка. На baseline первые два сценария обязаны воспроизвести изменение, на кандидате все четыре обязаны оставить блоки неизменными.

**Это проверка публичных методов, а не вызов настоящего повторного планирования light-engine.** Повторный старт повторяет стенд; он сам по себе не является проверкой сохранения всех пользовательских построек.

Отдельный natural_runtime оставляет существующий строгий тест и добавляет baseline-reverse и baseline-repeat. Всего шесть серверных фаз: baseline, candidate, restart, reverse, baseline-reverse, baseline-repeat. Сохранённая вода сравнивается после нормального stop; отсутствующая выборка не принимается. Оба дополнительных контроля включены в конечное AND, а не использованы для скрытия расхождений.
