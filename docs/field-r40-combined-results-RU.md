# R40 — объединённая заливка под островами: реальные результаты

Дата: 27 сентября 2026 года.
Статус: изменение ядра применено и реально скомпилировано, проведены серверные испытания. Ограниченная интеграционная приёмка НЕ пройдена. Готового пользовательского комплекта R40 не опубликовано.

## Изменения ядра и сборки

Ветка `fix/neveroverworld-r40-combined-ocean`, draft PR 22, база `c997bf574c0ec83243e99d4034736f49c1d6b246` из R39.9.
Исполняемый вход — именно проверенный R39.9, не исходный R38.

В R40 включены новый адаптер NeverOverworldOceanClosureR40 и вызов до расчёта освещения, после прежней очистки. Трёхмерный поиск OceanConnectivityR395 используется без изменения алгоритма. Положительный путь может идти сбоку под твёрдой крышей острова. Перезаписывается только AIR владельца, существующие жидкости и остальные блоки не являются целями записи.

Сохранена защита шахт через постоянную геометрию частей. Весь снимок владельца проверяется до первой записи: обнаруженный конфликт теперь останавливает проход вместо частичного применения.

Добавлен выключенный по умолчанию экспорт реального входа Java: коды всех клеток 3×3 чанка, открытые к небу колонки, дополнительные барьеры лавы и точная битовая маска записанного AIR. Отдельный Python BFS проверяет этот вход независимо от Java и требует точного совпадения целевых клеток. Он не использует только итоговый счётчик Java как доказательство.

Ядро по умолчанию не включает эксперимент без `-Dneverfolia.r395OceanClosure=true`. Имя флага историческое; в R40 вызывает новый класс R40. Экспорт свидетелей нужен только при диагностике, не для штатного ручного сервера.

## Что проверено

12 новых Python-тестов независимого обхода, 20 прежних Java-тестов solver и 8 тестов упаковщика прошли. Это разные наборы, не число серверных сценариев.

Синтетическая сцена на настоящем регионе: 17 именованных проверок, включая seed и границы мира. Проверены боковой вход под крышу, закрытая пещера, защищённая часть шахты с постоянными данными и без временного кэша, лава, лёд, текущая/падающая вода и неизвестный сосед. Тест вызывает тот же приватный close(), что production LIGHT-hook; публичный запрет повторной генерации FULL-чанка проверен отдельно.

Результат синтетической сцены: 30 AIR заменены водой, закрытая пещера и шахта остались сухими, исходные блоки и состояния воды сохранены. Независимый Python-проверщик подтвердил точную маску. Эта сцена не является естественно найденной шахтой.

Все семь природных серверных фаз завершились штатно с кодом 0 и свежими проверенными отчётами: baseline R39.9, baseline_repeat, baseline_reverse, candidate_off, candidate, restart, reverse. В каждой — те же 54 уникальных чанка в шести районах. Это не 378 независимых участков.
Полные состояния Name+Properties прочитаны из сохранённых чанков по Y=-512..511; сравнение водных состояний — Y=-511..128. Сущности, block-entity NBT и бой не входят в эти хеши.

Совпали полные состояния соответствующих пар: baseline / baseline_repeat; baseline / candidate_off; candidate / restart.
Полное совпадение прямого и обратного порядка по-прежнему отсутствует и в исходном R39.9, и в кандидате; этот результат отдельно сохранён как strict_generation_order_equal=false для обоих.

## Почему комплект не выпущен

В прямом сравнении R39.9 / R40 других изменений, кроме 7022 AIR → WATER, не обнаружено. В обратном сравнении обнаружены дополнительные **190** состояний блоков в двух чанках:
- (-190,-223): 154;
- (-189,-223): 36.

Высоты -25..37. Среди изменений — AIR/CAVE_AIR, BLUE_ICE/PACKED_ICE, глубинносланцевые кирпичи/плитки/ступени и 61 переход DIORITE → ANDESITE. Изначально runtime сохранял первые 32 примера, поэтому число 32 не заявлялось общим количеством; полный последующий обход установил 190.

Ни одна из этих 190 позиций не входит в битовую маску записей воды R40. Их конечная категория AIR/SOLID совпадает с категорией, записанной ДО прохода R40, во всех 190 случаях. Однако свидетели содержат категории, не точные имена льда и подтипы воздуха. Это не доказывает идентичность каждого исходного BlockState и не исключает косвенное влияние на порядок более ранних задач.

Сохранённые метаданные структур в обоих затронутых чанках совпали между сравниваемыми мирами. Присутствуют ссылки на nova_structures:catacomb, nova_structures:trial_dungeon и minecraft:mineshaft; в (-190,-223) сохранён старт catacomb. По этим ссылкам нельзя назначить конкретную структуру виновной без чтения её частей и процессоров.

Точная причина дополнительных 190 различий ещё НЕ установлена. Не включены исключения для льда и не ослаблена проверка сравнения одинакового порядка. Основной run сохраняет bounded_integration_pass=false и failure. Готовый тестовый ZIP не создан. Новый скомпилированный JAR не выдан пользователю как принятый.

## Следующий узкий шаг

Отделить нестабильность размещения/процессоров при повторе обратного порядка на исходном R39.9 от косвенного влияния нового LIGHT-прохода. Дополнительно проверить точные состояния перед LIGHT, а не только категории. После устранения или доказанного отделения причины повторить те же критерии приёмки — не перезапускать до первого случайного зелёного результата.

Общая полнота заливки за пределами окна 3×3, лёд из пользовательских скриншотов, все помещения данжей, клиентский интерфейс и прежние 95 ресурсных пробелов остаются открыты. Рабочие миры не менялись, draft PR 22 не слит. Последний выданный проверенный хотфикс — R39.9. Повторный ручной обход сейчас не нужен.
